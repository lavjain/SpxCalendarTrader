# Screen mockups

The images in [`docs/images/`](../images/) are generated by the scripts in this folder, so anyone can suggest a screen change by editing code and regenerating the images, before or while the real app is built.

| File | What it does |
| --- | --- |
| `data.py` | Builds a **simulated** SPX put chain with Black-Scholes and scores calendars with the repo's own `calendar_math.py` (sizing, greeks, skew, T/D, Θ/Mgn), plus break-evens, the expiry picker (short-leg DTE range, 3–7 day widths, holidays) and the strike rule (10s and/or 25s) |
| `render.py` | Lays out the screens as dark-theme HTML in the app's style (header with tabs and theme toggle, Tailwind slate colours, ⓘ popovers) and screenshots them with headless Chromium |

## Regenerate the images

From the repo root:

```bash
uv sync --group mockups                          # once: adds playwright and matplotlib (not app dependencies)
uv run --group mockups playwright install chromium   # once: downloads the headless browser
uv run --group mockups python docs/mockups/render.py
```

This rewrites `docs/images/*.png` and saves HTML copies in `docs/mockups/build/` (gitignored), which you can open in a browser for a quick look. A full run takes about 2–3 minutes, mostly the Holdings screen, which searches for entry and exit SPX levels that land each trade on the P/L it's meant to show.

To use a Chrome you already have instead of Playwright's Chromium, set `CHROME_PATH`, e.g. `CHROME_PATH="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"`.

## Suggest a change

1. Edit the screen's function in `render.py`: `finder_body(tab)` (with `filter_bar()`, `status_strip()`, `overview_box()` and `detail_ladder()` for the Calendars table, and `finder_panel(tab)` for the right-hand panel), `dialog_body()`, `close_dialog_body()`, `paste_dialog_body()` and `notes_body()` (rendered on their own, cropped to the dialog), `holdings_body(columns_open, on)` (columns listed in `HCOLS`; the trade panel is built inside it), the risk profile chart `risk_graph()` and the SPX chart `spx_chart()`, or `performance_body(tab, cond)` for the Performance sub-tabs. Styles are in `CSS` at the top.
2. Change the simulated market (SPX level, date, volatilities, sample trades) through the constants near each section: `NOW`, `S_NOW`, `ATM_S`, `ATM_L`, `OPEN`, `CLOSED`, `PREV`. The Finder's filter settings are `DTE_RANGE`, `WIDTHS_ON` and `STRIKES_ON`; the holiday list is `HOLIDAYS` in `data.py`.
3. Regenerate, look at the PNGs, and open a pull request with the code change and the new images. Say in the description what the change is for and, if it adds a column or rule, which section of [`docs/PLAN.md`](../PLAN.md) it would change.

## Rules

- **Numbers come from code.** Don't type prices, P/L or greeks into the HTML; compute them in `data.py` or `render.py` so every screen stays consistent.
- **Keep the yellow "Mockup" banner** on every image. These are not real quotes, trades or results, and the Performance page is random data that shows no edge.
- **The mockups follow the plan.** A mockup that adds something new is a proposal: it goes into `docs/PLAN.md` only once it's agreed.
